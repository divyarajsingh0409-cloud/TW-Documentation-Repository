# 8. Google Docs: collaborative document creation

## 8.1 What it is

Google Docs is a cloud-based word processor in Google Workspace. It supports document creation and real-time multi-user editing from different devices. It is suited to reports, meeting notes, proposals, specifications and shared class work.

## 8.2 Main capabilities

- Live collaboration with visible edits/cursors.
- Text formatting, headings, tables, images, drawings, links and equations.
- Comments and Suggesting mode for review.
- Automatic saving and version history.
- Import/export formats such as DOCX, PDF, ODT, RTF, HTML and plain text.

## 8.3 Structure a document properly

Start from a blank document or a template. Apply paragraph styles instead of manually formatting every heading:

- Title and Subtitle for document identity.
- Heading 1, Heading 2, etc. for hierarchy.
- Normal text for paragraphs.

Consistent heading styles make it possible to generate a table of contents and improve navigation, accessibility and export consistency.

## 8.4 Collaboration and sharing

Use **Share** to invite people by email or link. Assign the minimum appropriate permission:

| Permission | What it allows |
|---|---|
| Viewer | Read the document |
| Commenter | Read and leave comments |
| Editor | Change the document |

Use comments for feedback and Suggesting mode when proposed edits should be reviewed before becoming final text. Resolve comments when the discussion is complete.

## 8.5 Version history and recovery

Google Docs automatically saves changes. Open **File → Version history** to inspect earlier states and restore a previous version. Name important milestones (for example, Draft, Reviewed and Final) so the history is easier to understand.

## 8.6 Tables, lists, images and diagrams

- Insert tables to compare data or organize schedules.
- Use bulleted/numbered lists for structured points and checklists for action items.
- Insert images from a device or Google Drive; use the built-in Drawing tool for simple shapes and arrows.
- Diagram integrations such as diagrams.net or Lucidchart may support more complex visuals.

## 8.7 Equations and code

Use **Insert → Equation** for supported mathematical notation. For code snippets, use a monospace font or preformatted text so indentation and symbols remain readable. For larger code blocks, the lecture notes add-ons or image-based approaches.

## 8.8 Templates, citations and export

Templates can speed up reports and proposals. Headers, footers and page numbering help formal documents. Find/replace and spelling/grammar tools support editing.

Use **Tools → Citations** to manage sources in formats such as MLA, APA and Chicago, insert in-text citations and generate a bibliography. Citation managers such as Zotero or Mendeley can be integrated through add-ons.

Download a copy in a suitable format (PDF, DOCX, ODT, HTML, etc.) or publish to the web when public viewing is intended.

## 8.9 Permissions and data protection

Sharing controls should match the document's sensitivity. Restrict access to intended collaborators, review link-sharing settings and remove access when it is no longer required. Workspace administrators may apply organization-wide sharing policies.

## 8.10 Doxygen vs Google Docs

| Dimension | Doxygen | Google Docs |
|---|---|---|
| Main purpose | Code/API reference | General-purpose documents |
| Source | Special comments in source code | User-authored document content |
| Collaboration | Commonly through code/version-control review | Real-time multi-user editing |
| Typical output | HTML, LaTeX/PDF and other reference formats | Web document, PDF, Word and others |
| Best fit | Libraries, classes and APIs | Reports, proposals, meeting notes and specifications |

They solve different problems and can be used together: write project plans/specifications in Docs and generate API reference material with Doxygen.

Practice: create a document, apply heading styles, share it with a classmate in Commenter or Editor mode, add a comment, inspect version history and export a PDF.
